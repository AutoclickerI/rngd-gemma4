## Inputs and numerics

- `NV` is the [NVFP4 serving snapshot](../README.md#build-and-run). `BF` is [google/gemma-4-12B-it at `707f0a3b8a3c7ad586ed01e27eafbad8a27dd0f7`](https://huggingface.co/google/gemma-4-12B-it/tree/707f0a3b8a3c7ad586ed01e27eafbad8a27dd0f7). `capture.py` verifies the model files it uses.
- Activation uses eight BOS-prefixed 1,024-token WikiText-2 windows after skipping 20,000 nonempty rows, 64 CC3M images and 32 clips each from Zeroth Korean and LibriSpeech clean `train.100`. Media rows are sorted samples from the first 20,000 rows with seed 20261010 namespaced by source. Speech is 16 kHz mono PCM16. The teacher uses expanded FP8 attention and NVFP4 MLP stand-ins with FP32 accumulation and BF16 rounding boundaries.
- The head capture averages `x²` over post-final-RMSNorm rows within each context, then averages the 136 context means per channel. The historical fit used 4,679 rows across 148 equally weighted contexts, including 48 eSpeak NG speech contexts from original prose.
- Continuation generation uses 16 BOS-prefixed 512-token WikiText-2 windows after skipping 1,000 nonempty rows. It runs all 48 layers, then final RMSNorm, tied BF16 embedding logits with FP32 accumulation and Gemma's final softcap. It keeps the first 16 of 17 greedy tokens and masks EOS, end-of-turn, reasoning-channel and media-end tokens. Both teachers use the 256-position causal Sliding window that text requests served at when the Q4 fit ran (text later moved to 384), and no dithering. Generation and replay round Sliding KV to E4M3 and keep BF16 Full KV, with FP32 matmuls and TF32 disabled. The October teacher kept all KV in BF16 and ran in a research harness that also installed weight rotations, smoothing and a quantized head, which this teacher omits. Q4 replay observes 64 evenly spaced prompt rows and the 16 continuation rows.
- The October capture's receipt, `7f5b6419eb58f71cc899f88015c938d71fd2e1e74aaa0ff42e7c3b320bafef83`, is the historical calibration ID in `fp8_scales.json`. Recaptured scales carry their maxima's SHA-256, which `int8/fp8_scales.rs` rejects until its expected ID is changed. No server built from recaptured tables has run on a card. The shipped `activation-recorded.npz` hashes to `3485348b22d1fd943f918f851b9096ef910a91bedd7595cf8de7c475641f3f5f` (SHA-256).

Use Python 3.11+, PyTorch 2.13 (CUDA runs used 2.5.1 with CUDA 12.4), safetensors 0.7, PyArrow, tokenizers, Transformers, Pillow and soundfile. The fetcher uses datasets 3.6 and huggingface_hub. C generators use GCC/OpenMP, liblz4 and liblzma. Set `OPENBLAS_NUM_THREADS=1 TOKENIZERS_PARALLELISM=false`. Capture and fitting commands accept `--threads`. Captures take `--device cpu` (layer by layer) or `--device cuda[:index]`; CUDA continuation generation caches all layers' E4M3 weights.

## Shipped tables

The FP8 scale file holds 192 little-endian f32 activation peaks divided by 256, ordered QKV, O, MLP input and Down. INT8-S holds 1,335,296 signed exponent bytes. Each layer stores 3,840/3,840/15,360/4,096 exponents for QKV, MLP, Down and O (8,192 for Full O). Apply `2^e` to weight columns and `2^-e` to inputs. FP8 row indices decode to clipping ratios `0.5 + index / 32` for Gate, Up and Down.

Q4 startup packs signed Gate/Up smoothing exponents and little-endian FP16 row ratios into LZMA-alone with JSON indexing and validation. Head balance scales embedding columns by signed power-of-two exponents and folds reciprocals into final RMSNorm. Head clipping indices decode to `(30 + 2 × index) / 100` for the rotated embeddings with that diagonal. Compare sidecars as well as binaries.
